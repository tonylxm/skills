The pipeline: issue to merged PR

How one GitHub issue becomes a merged PR, and where you step in.

Contracts: pipeline · Decisions: pipeline-plan.md · Diagram on its own: flow.svg

How jobs run

  • One orchestrator runs up to 3 jobs at once.
  • Each job: its own worktree and branch, one PR that closes its issue.
  • Hitting any cap (3 check fails, 2 review rounds, 90 min, $15) sends the job to Needs human.
  • Issue labels (ready, in-progress, needs-human) are defined in pipeline.
